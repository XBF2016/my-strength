# 独特优势记录协议

## 核心定义

以后所有记录和讨论，都只围绕这 3 个定义标准：

1. 长期可持续：这类事情我能长期稳定做下去。
2. 学习速度更快：在这类事情上，我比多数人更快抓住关键、上手、形成方法。
3. 做得更好且有外部验证：结果更好，而且这种“更好”能被现实中的反馈、信任、机会、责任、合作或其他外部结果稳定证明。

补充说明：

- 兴趣、热情、历史积累、环境、资源，都不是“独特优势”的定义本身。
- 它们可以作为证据、背景或解释，但不能替代上面这 3 个定义标准。

## 记录门槛

不是所有口述内容都直接进入正式案例库。以后先做分类：

1. 事实案例：真实发生过，有具体行为、结果或外部反馈。
2. 混合案例：既有真实事实，也夹杂解释、设想或判断。
3. 假设线索：主要是偏好、设想、预测、自我描述，还没有完整真实事件支撑。

处理原则：

- 事实案例：可以直接整理成正式记录并打分。
- 混合案例：先提取事实核心；必要时先追问 1-2 个关键细节，再决定是否落入正式记录。
- 假设线索：不直接进入正式案例区，只进入“假设线索”区，不能和正式证据混为一谈。

## 混合式协作原则

以后我们的协作，不完全照搬人类咨询师，也不只是机械记录，而是采用“咨询师式澄清 + AI 式归档”的混合方式：

1. 你先自然口述，我先完整理解，不急着打分。
2. 我先区分事实、解释、感受/设想这三层。
3. 如果关键证据不够，我只追问最关键的 1-3 个问题。
4. 在事实清楚后，我再做分类、判断和写入。

这样做的目的：

- 保留咨询师式的理解质量
- 避免什么都直接落库
- 利用 AI 的结构化整理和长期对比能力

## 固定流程

以后每次记录内容，都按这 5 步走：

1. 我口述一个事实案例、混合案例，或假设线索。
2. Codex 先复述核心理解，并区分事实、解释、感受/设想。
3. 如果信息不够，Codex 先做最少量追问或先只提取有用部分。
4. Codex 再判断它属于事实案例、混合案例，还是假设线索。
5. Codex 只围绕 3 个定义标准做判断，并决定写入正式案例区还是“假设线索”区；每次写入后都要同步更新 `strength-system/case-index.json`。

## 索引规则

这个系统现在有五个数据层：

1. `strength-system/cases/`
这里存放所有正式案例文件，每个案例一个文件，这是正式案例的真相源。

2. `strength-system/hypotheses/`
这里存放所有假设线索文件，每条线索一个文件，这是低证据线索的真相源。

3. `strength-system/reviews.md`
这里存放跨案例复盘记录，这是复盘结论的真相源。

4. `strength-system/case-index.json`
这是自动生成的辅助索引，用来加速列表、清理、统计和复盘。它应该尽量轻量，只保留定位和摘要所需的信息。

5. `strength-system/case-library.md`
这是自动生成的人类可读总览，用来快速浏览，不是真相源。

规则是：

- 不允许只改索引或总览、不改源文件。
- `cases/`、`hypotheses/`、`reviews.md` 变化后，必须立即重建索引和总览。
- 索引应保持摘要化，避免重复存储展示型字段。
- 如果索引或总览缺失或过期，必须从源文件重建。

## 三项打分规则

每条案例都要对这 3 项分别打分，范围是 `0-2`：

- `0`：证据不足，暂时无法判断。
- `1`：有一定信号，但证据不够稳定或不够强。
- `2`：信号明确，证据较强。

对应项目：

- 长期可持续性
- 学习速度优势
- 外部验证的更优结果

## 正式记录格式

每条案例都按下面这个结构整理：

```markdown
## 正式案例 00X - 案例标题

- 日期: YYYY-MM-DD
- 来源: 用户口述案例
- 长期可持续性评分: 0-2
- 学习速度评分: 0-2
- 外部验证评分: 0-2
- 初步判断: strong signal | possible signal | insufficient evidence

### 事实

### 长期可持续性信号

### 学习速度信号

### 结果与外部验证

### 备注
```

## 假设线索格式

当内容主要是设想、偏好、预测，而不是已经发生并可验证的事实时，按下面格式记录：

```markdown
## 假设线索 00X - 标题

- 日期: YYYY-MM-DD
- 来源: 用户口述线索
- 状态: 假设线索

### 这条线索说明什么

### 为什么还不能算正式证据

### 需要什么证据来升级
```

## 推荐起手句

以后新开对话时，推荐直接这样说：

`请使用 $unique-advantage-journal，先读取 strength-system/protocol.md 和 strength-system/case-index.json，如有需要再打开相关 case 文件，然后严格按协议帮我记录接下来的案例。`
